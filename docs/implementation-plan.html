구현 계획: 레시피 카드 + 가격 힌트 웹 MVP

pnpm workspace + Turborepo monorepo에서 Next.js 웹 MVP와 Supabase 백엔드를 먼저 만들고, Expo 앱은 반복 사용이 검증된 뒤 확장한다.

Phase 1: 웹 MVP Monorepo: Turborepo Backend: Supabase Price Hint: mock first Expo: 검증 후

목표

사용자가 로그인한 뒤 레시피 링크를 붙여넣고, 레시피 카드 초안을 검토/수정한 다음 저장된 카드에서 재료와 조리 순서를 다시 볼 수 있게 만든다.

홈에서는 이번 주 해먹기 좋은 저장 레시피를 보여주고, 가격 힌트는 정확한 계산서가 아니라 메뉴 선택을 돕는 신호로 제공한다.

상세 작업

Task 1

Monorepo 생성

pnpm workspace와 Turborepo를 먼저 설정한다. 웹앱은 다음 Task에서 apps/web 아래에 만든다.

corepack enable
pnpm init
pnpm add -D turbo typescript
mkdir -p apps packages/shared/src packages/config supabase/functions supabase/migrations tests/e2e
  • pnpm-workspace.yaml이 있다.
  • turbo.json이 있다.
  • apps/*, packages/*가 workspace로 인식된다.
Task 2

Next.js 웹앱 생성

apps/web에 Next.js App Router 기반 웹 MVP를 만든다.

pnpm create next-app apps/web --typescript --eslint --app --no-src-dir --tailwind --use-pnpm --import-alias "@/*"
pnpm --filter web add @supabase/ssr @supabase/supabase-js zod
pnpm --filter web add -D vitest @testing-library/react @testing-library/jest-dom jsdom playwright
  • Next.js 기본 페이지가 빌드된다.
  • apps/web/lib/env.ts가 Supabase public env를 검증한다.
  • pnpm --filter web lint, pnpm --filter web build가 통과한다.
Task 3

Shared package 생성

웹과 앱이 공유할 순수 TypeScript 로직을 packages/shared에 둔다. 첫 공유 대상은 레시피 타입, URL validation, 추천 점수 계산이다.

  • packages/shared/src/recipes/types.ts
  • packages/shared/src/recipes/validation.ts
  • packages/shared/src/recommendations/scoring.ts
  • pnpm --filter @prepper/shared test가 통과한다.
Task 4

Supabase DB schema와 RLS 작성

레시피, 재료, 조리 순서, 파싱 소스, 가격 힌트, 추천 테이블을 만들고 모든 사용자 데이터에 RLS를 켠다.

필수 테이블

  • profiles
  • recipes
  • ingredients
  • recipe_steps
  • parsed_sources
  • price_hints
  • recommendations

검증

npx supabase start
npx supabase db reset
Task 5

Supabase Auth 연결

browser/server client를 분리하고, Google/Kakao OAuth 로그인 페이지와 콜백 라우트를 만든다. 이메일 링크 로그인은 제거하고 소셜 로그인만 제공한다.

  • apps/web/lib/supabase/browser.ts 생성
  • apps/web/lib/supabase/server.ts 생성
  • apps/web/app/login/page.tsx 생성
  • 카카오로 계속하기 / Google로 계속하기 버튼 제공
  • Supabase Google/Kakao provider enable 확인
  • Google Cloud Console Web OAuth client에 Supabase callback URI 등록 확인
  • Supabase URL Configuration에 로컬 앱 callback URL 등록 확인
  • 로그인 성공 후 /recipes로 이동
Task 6

레시피 URL 검증 로직

빈 문자열, 잘못된 URL, private IP, 지원하지 않는 scheme을 막고 YouTube와 일반 웹 링크를 구분한다.

pnpm --filter @prepper/shared test -- url-validation.test.ts
  • 빈 문자열 거절
  • URL이 아닌 값 거절
  • localhost, 127.0.0.1, private IP 거절
  • YouTube URL은 sourceType = youtube
  • 일반 URL은 sourceType = web
Task 7

수동 레시피 CRUD

외부 API 없이도 레시피 카드를 직접 만들고 저장하고 검색하고 상세에서 볼 수 있게 한다.

  • /recipes/new: 원본 링크, 제목, 재료, 조리 순서 입력
  • /recipes: 검색 입력, 저장된 레시피 목록, 빈 상태
  • /recipes/[id]: 제목, 재료, 조리 순서, 원본 링크
  • 다른 사용자의 레시피는 보이지 않음
Task 8

링크 import + review 흐름

URL을 붙여넣으면 기본 parser가 초안을 만들고, 사용자가 review 화면에서 확인 후 저장한다.

YouTube는 YouTube Data API로 title/description을 가져오고, description에 레시피 단서가 부족하면 공개 caption track의 transcript를 LLM 입력에 추가한다. 일반 웹/블로그는 HTML에서 읽을 만한 본문 텍스트를 추출해 OpenAI Structured Outputs 기반 LLM parser에 보낸다. API 키가 없거나 파싱이 실패하면 기존 fallback parser와 review warning을 사용한다. 
importing -> needs_review -> saved
importing -> failed
failed -> importing
  • supabase/functions/import-recipe/index.ts 생성
  • apps/web/app/recipes/[id]/review/page.tsx 생성
  • 사용자 검토 없이 saved가 되지 않음
  • double submit 방지
  • 구조화 데이터가 일부 다른 웹 페이지도 재료/순서 후보를 채움
  • 제목만 가져온 초안은 review 화면에서 재료/조리순서 확인 경고를 보여줌
  • YouTube description/transcript 또는 일반 웹 본문에서 LLM parser가 재료/조리순서 초안을 만듦
  • YouTube description/transcript 모두 레시피 정보를 충분히 제공하지 못하면 review warning을 보여줌
Task 9

Mock 가격 힌트

실제 Coupang 연동 없이 가격 힌트 UX를 검증한다.

가격 힌트는 정확한 총 재료비가 아니라 메뉴 선택을 돕는 신호다. "최저가", "오늘이 가장 싸다", "총 재료비" 같은 표현은 쓰지 않는다.
  • 주요 재료 최대 3개만 대상으로 함
  • provider는 mock
  • band는 cheap, normal, expensive, unknown
  • 가격 힌트 실패가 레시피 저장을 막지 않음
Task 10

추천 홈

저장된 레시피 중 이번 주 해먹기 좋은 메뉴를 보여준다. 가격 힌트가 부족하면 최근 저장순으로 fallback한다.

score =
  price_signal_score
  + recency_score
  + favorite_score
  - low_confidence_penalty
  • 저장 레시피 없음: "레시피를 먼저 저장해보세요"
  • 가격 힌트 없음: "가격 정보 없이 최근 저장순으로 보여드려요"
  • 추천 있음: "이번 주 해먹기 좋은 저장 레시피"
Task 11

핵심 E2E 테스트

브라우저에서 레시피 생성과 상세 조회 흐름을 검증한다.

pnpm --filter web dev
npx playwright test tests/e2e/recipe-flow.spec.ts
  • /recipes/new 이동
  • 원본 링크, 제목, 재료, 조리 순서 입력
  • 저장
  • 상세 페이지에서 제목, 재료, 원본 링크 확인
